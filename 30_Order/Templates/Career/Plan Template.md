# <% tp.file.title %>
==One sentence stating what this plan gets you and by when — if you can't write this sentence yet, the plan isn't ready to create.== Full process for using this template: [[10_Areas/Life/Plans/Plans-to-Create|Plans-to-Create]]. Cadence and staleness rules: [[30_Order/Standards/Daily Workflow Standard|Daily Workflow Standard]].
## Goal
One or two sentences. One metric that proves the goal was hit, not a vibe. If the goal needs a paragraph to explain, it isn't scoped yet — cut it down before filling in the rest of this template.
## Timeframe
Start date, end date, and the reason the end date is real (an external deadline, a semester start, a flight) rather than aspirational. If there's a multi-week span, add a week-by-week or phase table here — dates only, no vague "eventually."
## Systems
How the goal breaks into concrete, checkable tracks. Each track needs a cadence (daily, weekly, per-flagship) and a done-definition. A system that can't be checked off on a given day isn't a system, it's a hope.
## Implementation Status
Filled in only from verified evidence — a real file, a real commit, a real `git log`, a real tracker — never from memory of intent. State plainly what's built, what's planned-but-not-built, and what's untouched. This section is what separates a real plan from a wish list; do not soften it.
## Current Progress
Living section. Append a dated line every time this plan gets reviewed — don't rewrite history, add to it. If this section goes silent for longer than the `review_cadence` field says, that's the signal the plan itself has gone stale, per [[30_Order/Standards/Daily Workflow Standard|Daily Workflow Standard]].
## Update Protocol
State exactly when this note must be revisited: which skill or review touches it (`/closeday`, `/weekly-review`, a monthly review), and what happens if that review is missed twice in a row. A plan with no update protocol is the exact failure mode this template exists to prevent — see [[10_Areas/Life/Plans/Plans-to-Create|Plans-to-Create]] for why.
