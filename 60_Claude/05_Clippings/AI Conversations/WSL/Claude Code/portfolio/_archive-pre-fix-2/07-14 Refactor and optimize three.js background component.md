## Root cause

`PortfolioContent.tsx:41` wraps every section in a single `<main className="relative z-10 min-h-screen ...">` that spans the entire page — full width, full scroll height. Because it's `position: relative` with `z-index: 10`, it's the topmost element at **every** pixel of the page, including the "empty" background areas where only the sphere is visible. My previous fix (`pointerEvents: "auto"` on the canvas wrapper) was necessary-but-not-sufficient — it made the canvas capable of receiving clicks, but `<main>` still sits on top of it everywhere in paint order, so a DOM click event physically never reaches the canvas. No CSS `pointer-events` value on the canvas side can fix that; the blocker is on the content side, and touching `<main>`'s pointer-events would risk breaking real UI clicks across every section.

## Fix

Bypassed DOM event routing entirely. The component already tracks the cursor via a `window.addEventListener("pointermove", ...)` listener for the magnetic-pull effect — same idea, extended to clicks: a `window` `"click"` listener converts the click coordinates to NDC space and does a manual `THREE.Raycaster` intersection test against the invisible hit-sphere (`ObsidianBackgroundCanvas.tsx:432-442`). This fires on the bubble phase regardless of what visually painted on top, and only triggers the burst if the ray actually lands on the sphere's current (scroll-scaled) geometry.
