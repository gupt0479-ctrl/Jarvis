princeton CS. building AI tools. i post what i use.

last updated June 15th, 2026

LeetCode isnt dead. it just stopped being the thing that gets u hired. the test moved to the actual job, debugging, reviewing PRs, writing tests, and catching AI when its confidently wrong. these are the 5 things id study, ranked.

the throughline is judgment. every link below trains the same thing, knowing what to do when the test is broken, the PR is sketchy, or the model is confidently wrong. read top to bottom, but do the reps. dont just skim.

### 1\. SadServers

[try it →](https://sadservers.com/)

broken Linux boxes, a timer, fix it or fail. closest thing to the actual job there is, and almost nobody trains this muscle. start here.

do the reps, not the reading. pick one scenario, give urself 30 minutes, no AI. the panic of a broken prod box is the exact thing they screen for.

### 2\. the Testing Trophy by Kent C. Dodds

[read it →](https://kentcdodds.com/blog/the-testing-trophy-and-testing-classifications)

if u can write strong tests, u actually understand the code. tests are also how u catch AI when its confidently wrong. this breaks down what to test and what to skip, so u stop writing tests that prove nothing.

### 3\. the Google code review guide

[read the guide →](https://google.github.io/eng-practices/review/)

how real engineers actually review a PR. then go open real pull requests on GitHub and try to spot the issues BEFORE u read the comments. insanely underrated skill.

turn it into a drill. find a merged PR in a big repo, review the diff blind, then read what the maintainers caught. the gap between ur list and theirs is ur study plan.

### 4\. MIT Missing Semester, debugging and profiling

[read it →](https://missing.csail.mit.edu/2020/debugging-profiling/)

narrowing scope and tracing a bug to its root cause, fast. if u cant do this ur not production-ready. its the stuff the CS degree skips and the job assumes u already know.

### 5\. HackerRank, AI-assisted interviews

[hackerrank →](https://www.hackerrank.com/)

grab the current guide, search "HackerRank AI-assisted interviews"

more companies now let u use AI in the interview, then grade ur judgment instead of raw output. ur prompts can be visible to the interviewer. read up so the format doesnt catch u off guard on the day.

LeetCode still gets u the interview. judgment is what gets u the offer.
