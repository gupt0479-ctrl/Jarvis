# Internship Research Loop — Source of Truth
==The complete, closed statement of what this system is built to do — target scope, current form, in one place.== This is not a build report — [[System - Build Log]] carries the full dated history of every session, what shipped, what's still uncommitted, and why each decision landed where it did. Read that note for *how we got here*; read this note for *what's true about the finished shape right now*.
## What This System Is
Two halves, deliberately different in rigor. **Discovery** is a GitHub Actions workflow (`gupta-builds/internship-research-loop`) that polls eight internship-listing sources hourly, filters through a zero-Claude/Anthropic-LLM deterministic gate, and writes survivors into `10_Areas/Career/Internships/List/Dossiers/` — mechanical, unattended, cheap by design. **Promotion onward** is entirely manual, human-judgment-driven, and stays that way on purpose: a dossier becoming a Program note, a Program note turning into real outreach, an outreach turning into a submitted application — none of that is automated, none of it should be.
## The End Goal, Stated Plainly
A real Summer 2027, Winter 2027 (Dec-Jan), or lower-priority Spring 2027 SWE/AI internship, open in the US and OPT-eligible, reaches this vault within an hour of going live anywhere it's discoverable — already carrying enough real content that deciding whether to pursue it takes 60 seconds, not a webpage visit. **A dossier landing in `List/Dossiers/` is not the finish line.** The finish line is a submitted application, and the loop only earns its cost once dossiers are actually promoted through [[30_Order/Workflows/Internship Pipeline]] into real Program notes, real contact research, and real outreach. The success metric is applications submitted per week — not dossiers written, not tests passing, not folders looking tidy.
## The Four Hard Gates — What Has To Be True Before A Dossier Exists
All four share one design principle, applied consistently since the very first rule (`locations_allow`, Phase 2): **permissive by default, exclude only on an explicit negative signal.** A false exclusion silently loses a real opportunity with nothing to show for it; a false inclusion costs one human screening read. That asymmetry is why every rule below errs toward keeping, not discarding, when a signal is ambiguous.
1. **Timing** — `terms: ["Summer 2027", "Winter 2027", "Spring 2027"]` in `core/profile.yaml`. Summer 2027 and Winter 2027 (genuinely Dec 2026-Jan 2027, not the full "Winter" label bucket) are equally high priority; Spring 2027 is wanted but explicitly lower-weighted (`terms_weight`), never a second pass/fail gate.
2. **Location** — United States. An affirmative US signal always passes; an affirmative foreign signal always rejects; anything ambiguous (no data, "Remote," "Multiple Locations") passes. **Design correct, implementation has real gaps as of the 2026-08-23 audit**: `location_eligible()`'s `_NON_US` denylist is missing Netherlands, Hong Kong, Poland, Israel, and bare city names — live, confirmed passes that shouldn't have (Marshall Wace Hong Kong/London roles, two Optiver Amsterdam roles, three more in AI & ML). Not yet fixed; see [[System - Build Log]]'s 2026-08-23 entry.
3. **OPT eligibility** — checked per posting, not per company (the same company can differ role-to-role — proven directly by the 2026-07-19 dossier audit finding Palantir's US Government role citizenship-gated while its Commercial role wasn't). OPT ≠ H-1B sponsorship; "no visa sponsorship" alone is never an exclusion signal. Excluded only on an explicit citizenship/US-person requirement, a security-clearance requirement, or an explicit "OPT/CPT not accepted" statement.
4. **CS/software relevance — added 2026-07-26.** A listing must be genuinely computer science / software engineering at its core, checked *after* the three criteria above, before a dossier is ever written. Adjacent fields (hardware, robotics, astrophysics, space, firmware) are not auto-excluded — they pass only if the specific posting's real content shows genuine software/CS relevance the candidate is suited for (grounded in `Main Resume.md` and `Engineer Edge Roadmap.md`, not guessed). Anything with no software content at all (financial/risk analyst, tax, sports-performance analytics, pure trading-strategy research) is rejected outright and does not land anywhere — not even `Other`. **Design correct, implementation has a real recurring gap as of the 2026-08-23 audit**: `_ADJACENT_FIELD_COMPANY_HINT_RE` doesn't cover generic business/finance/BI role families, so `stage2_confirm` short-circuits past a real content check on them — confirmed live passes that shouldn't have (UHY Data Operations, Walleye Finance & Accounting, CNO Reporting Analyst, Vertiv ×2, FTI Technology ×2, KeyBank Data, others). Separately, a genuine SPA content-extraction bug (Zipline/AIJobs, 49 `Other`-bucket dossiers sharing one fetched board-index page instead of each posting's real content) lets this same gate pass roles it never actually evaluated. Neither fixed yet; see [[System - Build Log]]'s 2026-08-23 entry.
## Priority Classification — Where A Surviving Dossier Lands
Everything that clears all four gates gets sorted into exactly one subfolder under `List/Dossiers/`, with a short callout at the top citing the real signal that drove the call — never a numeric "Priority N" label; the folder itself is the label:
- **`1 - AI & ML/`** — LLM, RAG, agents, ML infrastructure, applied AI, deep learning signals.
- **`2 - Fullstack/`** — product/frontend/backend/systems engineering, no AI/finance-specific signal.
- **`3 - CyS & Finance/`** — security engineering, or software engineering inside a finance/trading firm.
- **`Other/`** — genuine software engineering that fits none of the three niches above. Same research rigor applies here as anywhere else — this is not a lesser bucket, it exists because "real but not a stated priority" is a legitimate, common case (defense contractors, industrial/embedded software, general enterprise SWE).
`Viewed/` sits alongside these four as a human triage bin (seen, not used) — it is never a pipeline write target. **A real, unfixed bug as of the 2026-08-23 audit**: `recheck.py`'s `plan_removals()` re-sweeps `Viewed/` itself, never checking `status == "removed"` — a dossier that stays closed gets re-processed and re-moved every day forever, accumulating a `(2)`, `(3)`... filename-collision suffix. All 4 real dossiers in `Viewed/` as of 2026-08-23 carry this suffix; all 4 are otherwise correctly classified as genuinely closed, so this is a re-processing bug, not a misclassification one. Not yet fixed.
## Resource Limits — Shipped And Live As Of 2026-08-21
A **notification system, never a write refusal** — a full bucket is a signal to review more urgently, not a reason to silently drop a real, currently-open posting, consistent with this codebase's founding permissive-by-default asymmetry. Per push, `MAX_NEW_WRITES_PER_RUN` caps new writes at 3 AI/ML, 3 Fullstack, 3 CyS & Finance, 1 Other (`run_pipeline.py`) — each bucket draws only from its own ordered queue, so an empty bucket this run can't let another bucket borrow its slots. Ordering within a bucket is the **debate comparator** (`core/debate.py`): preferred-company tier (`core/profile.yaml`'s `preferred_companies`) → bucket fill-need → recency. A candidate that loses the comparator's sort 5 consecutive runs (`MAX_DEBATE_LOSSES`) moves to a reviewable, append-only log (`Excluded — Losing The Debate.md`) — never a silent permanent drop. Each priority bucket has a **50-dossier notification threshold** (`BUCKET_CAPACITY`); the global total (excluding `Viewed/`) logs informationally at 150/170 and files a GitHub issue at 190/200 (`GLOBAL_INFO_THRESHOLDS`/`GLOBAL_ISSUE_THRESHOLDS`). **Confirmed live, not just committed**: a manual `run.yml` trigger on 2026-08-21 fired `bucket_at_capacity: ["AI/ML", "CyS & Finance", "Other"]` and `dossier_total: 393` in the real run record, and issues #4-8 were auto-filed the same run for real threshold crossings (3 buckets over 50, global past 190 and 200) — not a hypothetical, an actual first firing. `dossier_total` was 391 as of the most recent 2026-08-22 run (recheck.py moving closed postings to `Viewed/` between runs). Resource exhaustion (a source running dry of new eligible postings) still gets logged in `10_Areas/Career/Internships/List/Resources` with the planned alternative named in `[[20_Progress/Internship/Building System/Research Loop - Resources]]` (unchanged by this shipment).
**A real design gap, found by the 2026-08-23 audit, not fixed yet**: the debate comparator's preference tier is a flat binary — every "high"-tier company ties at rank 0, so recency is the only real tiebreaker among tied preferred companies, against a small fixed per-bucket budget. A genuine arrival burst on 2026-08-21 converted 287 of 304 `Excluded — Losing The Debate.md` entries (94%, including 106 of TikTok's 107) into permanent exclusions within roughly 5 hours — including a real preferred-company posting (Citadel) losing purely to fresher preferred-company arrivals in the same tiny bucket, not to worse candidates. The mechanism itself isn't broken (`company_matches_preference()` resolves Citadel's tier correctly); the gap is that the design can't distinguish "genuinely undesirable" from "the queue is temporarily backed up," and the same excluded pool hides real non-technical roles (Zipline, Varda Space, Astranis) that never reached the content-fetch stage that would otherwise catch them, since excluded candidates never reach `validate_and_write`. Full detail: [[System - Build Log]]'s 2026-08-23 entry.
**Cross-source dedup, status as of the same audit**: commit `722ca4d`'s URL-job-id fix is confirmed working going forward — no new duplicate has appeared since it landed. ~53 duplicates in ~23 groups from before that commit are still sitting live in the vault, uncleaned, plus two live mechanisms that still produce new duplicates today: zero ATS-job-id coverage for Workday postings, and a checkout-freshness race on platforms that do have job-id coverage. Not yet fixed.
## The Promotion Pipeline — Dossier To Submitted Application
Full step-by-step reasoning lives in the new detailed workflow note (`30_Order/Workflows/`, in progress); the short version:
```
Dossier (auto, priority-sorted)
  -> Screen: the fit test (goal-push + personal fit; contact-reachability noted, never gated; pay never a factor)
  -> Commit: Program note (Serious/ or Considering/, identical rigor) + Contacts/Each One (Ongoing/) + Tracker/Each One (Current/)
  -> Reach out via the Contact note's live draft, built from Mimic.md
  -> Ready to actually apply: Job & Company note (deeper, interview-prep-grade company/role research)
  -> Apply: Applying/Now.md entry + an Applied note; Program note moves to its Ended/ subfolder
  -> Outcome: Tracker note's result field set; Contact moves to Ended/ (concluded) or Come Back/ (revisit later)
```
Anything sitting in a Program `Ended/` folder with no matching note in `20_Progress/Internship/Applying/` gets discarded — `Ended` means applied, and if there's no Applying record, it never actually left the research phase and shouldn't claim otherwise.

## Explicit Non-Goals
No CAPTCHA-bypass, cookie-injection, or stealth-browser automation against LinkedIn or any login-walled platform, at any phase — a scoped Firecrawl *search* for public LinkedIn snippets is the one sanctioned exception, and it never fetches the underlying LinkedIn page. No Claude/Anthropic LLM call anywhere in the unattended discovery/recheck/OPT-check/classification path — Firecrawl's own extraction runs on Firecrawl's infrastructure and was never in scope for this restriction. Contact discovery uses public sources only.

## What "Closing The Loop" Means Here
Discovery (find through write-gate, including the CS-relevance gate and priority classification) was independently verified solid, repeatedly, by fresh sessions with no stake in the prior claims — through 2026-08-21. **That verification is now stale.** A 2026-08-23 research-only audit (six parallel forks, all 390 live dossiers, report only — nothing removed or fixed) found the *design* in this note is still right but the *implementation* has real, currently-unfixed gaps: a SPA content-extraction leak, lingering pre-fix cross-source duplicates plus two still-live dedup gaps, a location-denylist gap, a business/finance-role relevance-gate gap, a `Viewed/` re-processing bug, and the debate-comparator design gap above. See each Hard Gate and the Resource Limits section above for the specific, cited findings, and [[System - Build Log]]'s 2026-08-23 entry for the full list. **That has never been the same thing as this loop being finished, in either direction** — the 2026-07-26 session proved the promotion half can actually work (the Appian promotion, plus three manual-web-find promotions on 2026-07-29, all still pre-application), and the code behind it (the `/promote-dossier` skill, `contact-researcher` agent, priority classification) is committed and live. The dossier count-limit spec, the debate comparator, and recheck-to-Viewed all shipped 2026-08-21 and are confirmed firing against real fresh runs — firing correctly does not mean firing bug-free, per the 2026-08-23 findings above. Fixes for all of it are queued for a future prompt (Prompt 10), not yet run as of this writing. Read [[System - Build Log]] for the exact, current gap between "designed," "live," and "correct."
