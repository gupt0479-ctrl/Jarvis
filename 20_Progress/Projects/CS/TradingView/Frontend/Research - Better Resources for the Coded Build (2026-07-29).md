# Research — Better Resources for the Coded Build (2026-07-29)
==The previous research pass (2026-07-26) gave you a correct but fragmented toolkit — one library per job. This pass found the actual niche upgrade: a small number of tools built for problems structurally identical to yours, not just adjacent to it.==
## The one upgrade worth taking seriously: Apache ECharts replaces two of your seven libraries with one
**`apache/echarts`** — `https://github.com/apache/echarts` — 66.9k stars, Apache Software Foundation project (originated at Baidu, now fully ASF-governed), continuously maintained since 2018, genuinely one of the most mature charting libraries in existence. It natively supports a **candlestick series** built specifically for OHLC financial data, and a **graph series** — a real force-directed node/edge network with built-in physics, clustering, and smooth animated layout transitions — in the *same library*. This means `lightweight-charts` (for price/TA charts) and `react-force-graph` (for Brain-Journal and Bots-Hub) could both be replaced by one dependency instead of two, with one consistent theming system, one animation language, and one library's worth of documentation to learn instead of three. Its companion, **`ecomfe/echarts-gl`** (`https://github.com/ecomfe/echarts-gl`, 2.7k stars, official ECharts extension) extends this into real 3D — 3D graphs, 3D surfaces, 3D scatter — which is exactly the production-phase cinematic upgrade path Brain-Journal's graph and Bots-Hub's swarm are waiting on, using the same data and API shape as the 2D version. This is the single strongest "upscale" available: one coherent visualization system spanning candlestick charts, network graphs, and their eventual 3D forms, from one team, one design language.
**Verdict:** worth trialing directly in the prototype instead of `lightweight-charts` + `react-force-graph`. The only real tradeoff is that `lightweight-charts` is a lighter, more purpose-built tool specifically for financial candlestick charts and slightly faster to integrate for that one job — if you want the fastest path to a working price chart today, keep it; if you want one library covering the whole desk's visualization surface long-term, ECharts is the better bet.
## A sharper alternative for the 2D graphs specifically: sigma.js
**`jacomyal/sigma.js`** — `https://github.com/jacomyal/sigma.js` — 12.1k stars, mature (predates react-force-graph), WebGL-rendered, purpose-built for large interactive network graphs with a much more polished out-of-the-box visual style than `react-force-graph`'s default look. If ECharts' graph series feels too generic once you actually try it, sigma.js is the more graph-specialist option — it's what a lot of real knowledge-graph and network-analysis tools reach for specifically because it was built for exactly this job, not adapted from a general charting library.
## For the eventual true-cinematic, large-scale graph: cosmos
**`cosmosgl/graph`** — `https://github.com/cosmosgl/graph` — 1.2k stars but genuinely notable: a GPU-accelerated force-graph layout engine capable of rendering hundreds of thousands of nodes at 60fps, built by the team behind Cosmograph. This is real headroom — Brain-Journal's graph today has a handful of nodes, but a desk that's been running for a year could have thousands of journal entries, and this is the library that scales to that without falling over. Worth keeping in your back pocket for the production-phase 3D build specifically, once node count actually starts to matter.
## The precise niche match for Bots-Hub: Langfuse
**`langfuse/langfuse`** — `https://github.com/langfuse/langfuse` — 32.1k stars, YC-backed, MIT-licensed for self-hosting, one of the most widely used open-source LLM observability platforms in production today. This is not a UI kit to fork — it's a real product whose entire job is visualizing exactly your Bots-Hub problem: multi-step LLM agent pipelines (their equivalent of your Ingest-Bot → FactorEngine → Analyst → Critic → GateRunner chain), showing which step ran, how long it took, what it cost, and a full trace/log view with filtering. Don't clone its code — **look at its actual hosted or self-hosted dashboard UI** for how a mature, funded team solved "show me what my AI pipeline is doing right now" — their trace-timeline view and cost-tracking panels are the closest real-world precedent to Bots-Hub's Logs tab and Dashboard's backend-ops cost line that exists anywhere. This is a genuinely different category of resource than a GitHub repo to `npm install` — it's the best available answer to "how did someone who does this professionally actually solve it."
## A real, if small, precedent in your exact niche
**`Hitheshkaranth/OpenTerminalUI`** — `https://github.com/Hitheshkaranth/OpenTerminalUI` — only 67 stars, an early-stage open trading-terminal UI (market data, charting) — genuinely the closest thing found to "someone building a dark-themed trading research terminal UI in the open," but too small and unproven to trust as a dependency or even a serious design reference. Worth a five-minute look for "did anyone already solve a layout problem I'm about to hit," not worth building on.
## What a real professional-grade "mimic" actually looks like here, honestly
You asked specifically to go deeper than generic dashboard templates and find someone doing what you're doing, done by a professional quant or AI engineer. Having now searched specifically for that: **it doesn't exist as one open-source repo**, and that's worth saying plainly rather than forcing a weak match. The reason is structural, not a search failure — the exact combination you're building (deterministic factor math feeding an LLM analyst/critic pair, gated by classical statistical tests before paper money touches it, with a UI that shows the reasoning trail as prominently as the numbers) sits at an intersection three different professional communities each only cover one third of: quant researchers build Qlib-like factor platforms with no UI and no LLM layer; LLM/agent engineers build LangSmith/Langfuse-like observability tools with no financial domain logic; dashboard builders build OpenBB/freqtrade-like trading UIs with no evidence-based reasoning layer. Nobody public has stitched all three together the way this project does, which is genuinely the honest answer to "why can't I find this already built" — not that the search wasn't deep enough. The real shortcut isn't a single repo to clone; it's exactly what the previous and this research pass already handed you: Qlib's factor math, a graph library from this note for the brain visualization, Langfuse's dashboard as a reference for the agent-ops view, and TradingView's own chart engine (or ECharts) for the financial half — assembled by you, because nobody else has needed this particular combination badly enough to build and open-source it first.
## Updated recommendation, in order
1. **Trial Apache ECharts** for both the price/TA charts and the two network graphs before committing further to the three-library split from the previous pass — it's the single biggest simplification available and it scales cleanly into the 3D production phase via echarts-gl.
2. **Keep `tsparticles`** for Bots-Hub's eventual true particle-swarm production upgrade — nothing found in this pass beats it for that specific effect.
3. **Browse Langfuse's dashboard** (self-hosted demo or their docs' screenshots) as direct visual reference for Bots-Hub's Logs tab and any future cost-tracking UI — this is the closest real precedent that exists.
4. **Keep sigma.js and cosmosgl/graph noted** as upgrade paths specifically for Brain-Journal if ECharts' graph series or react-force-graph's default look doesn't feel polished enough once you actually see it rendered.
5. Stop searching for "the one repo that's already this exact product" — it doesn't exist, and the reason why is itself useful context for how unusual and worth finishing this project actually is.
