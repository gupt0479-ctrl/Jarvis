# Session Findings — AI Brain Hub (2026-07-12)
==This note is the current SoT for the AI-hub questionnaire (A1–F2). It does not supersede [[Session Findings — Post Base (2026-07-11)]] on ingestion/Phase 2b facts — it extends the loop with the self-improving AI harness design that Post Base explicitly deferred ("analyst/critic agents; UI/charting" listed there as not-yet-built).==
## Goal
Cursor ran a locked questionnaire (A1 through F2, ~20 questions) to design the **AI hub** — the analyst/critic harness that turns deterministic packets (`ScorePacket`, `DataEvidencePacket`, gate `TestRunRecord`s, paper `JournalEntry`s) into a human-gated **`EvidenceCard`** and **`CriticReview`**, on top of the `demo_eligible` `quality_momentum_tilt_top3` pack that landed in PR #3. Every decision below was cross-checked against the actual repo code (not assumed from the questionnaire's own framing) before being locked — several answers correct or tighten what Cursor proposed based on what the code actually does.

Confirmed explicitly:
- **V1 altitude:** this session's V1 = the AI hub only (Analyst + Critic on the `demo_eligible` pack), matching Cursor's original A1 framing. The fuller vision gets written down as its own north-star doc, not built now.
- **Prediction-market vertical:** stays parked, untouched. [[Postmortem - Stocks-ETFs First, Prediction Markets Second]]'s precondition ("stocks/ETFs paper trading online, tested, verified real-use ready") has not been met — Phase 2b is `demo_eligible`, not live-paper-proven. `tests/test_package_invariants.py` still hard-fails on any `kalshi`/`polymarket`/`prediction_market` path fragment.
- **UI:** does not exist and is not built in this phase. Confirmed by grep (zero Streamlit/dashboard code in the repo) and by [[Session Findings — Post Base (2026-07-11)]]'s own explicit deferral list.

## Block B — Packet Contracts
*Mechanism:* the LLM may only ever see structured packets already computed by deterministic Python — never raw OHLCV, never Kronos, never anything it could use to invent a number.
| ID | Decision | Key notes |
|---|---|---|
| **B1** | **D + amendments** | Analyst quotes numbers from **`ScorePacket`** only; `DataEvidencePacket` contributes `evidence_refs`/citation handles only — its `PacketDataQuality` and the packet's own `quality_status`/`confidence_cap` are not both serialized (real overlap found by reading `factors/packets.py` + `models.py:269`). Critic gets a fixed whitelist projection of `TestRunRecord` (`oos_net_sharpe`, `mc_p5_return`, `wf_pct_positive`, `deflated_sharpe_probability`) via a new **`GateSummaryProjection`** — not the raw `inputs`/`outputs` dict, which is untyped `dict[str, Any]` per gate module today. Live gate keys today are `oos_sharpe`, `tail_annualized_return`, `fraction_positive`, `deflated_sharpe_probability` — the projection renames, never recomputes. Plus `PromotionDecision` + relevant `JournalEntry`s. Kronos never attached. Raw `FundamentalsSnapshot` only if `ScorePacket` marks `INSUFFICIENT_DATA` |
| **B2** | **B** — Pydantic `EvidenceCard` in `cards/models.py` + `schema_version`; CLI writes `data/cards/{symbol}_{as_of}_{card_id}.json`; goldens on fixtures; vault YAML becomes a mirror example, not SoT; **`CriticReview`** is a separate model, not jammed into the card | *Sequencing (not reopened):* DuckDB `evidence_cards` table is **build #2**, started only after goldens pass and the live A3 card hasn't needed a breaking field change. Mirrors `raw_market_payloads`'s existing hash+path pattern (`card_id` PK, `card_path`, `symbol`, `as_of`, `schema_version`, nullable `spec_id`) — this repo has no migration mechanism (schema changes = backup + rebuild the DuckDB file, per the existing `.bak-*` files), so committing the table before the card shape stabilizes means rebuilding two artifacts instead of one |
| **B3** | **D** — post-validator (allowlist) + critic (adversarial second pass), built from `ScorePacket` + `GateSummaryProjection` + journal floats | The allowlist matcher must use **tolerance-based numeric matching, not exact string containment** — this repo already renders floats rounded (`walk_forward.py`, `cli.py`, `benchmark.py` all format to 2–6 decimals), so a true card will never literal-match a raw `ScorePacket` float. Two typed buckets: float performance numbers matched within a rounding epsilon (pinned in the golden tests themselves); structural ints (`rank`, `universe_size`, `ranked_count`, `window_sessions`, `overlapping_sessions`, `price_rows_used`) matched exactly, no tolerance |
| **B4** | **D** — hard clamp + critic monotone | Confidence cap SoT = `ScorePacket.data_quality.max_confidence` only. Reject `confidence > max_confidence`. `CriticReview.confidence_delta ≤ 0` (critic may only lower, never raise). Final confidence = `min(analyst, critic-adjusted, cap)` |
## Block C — Agent Topology
*Mechanism:* thin roles bound to packets, not a multi-agent debate deciding outcomes.
| ID | Decision | Key notes |
|---|---|---|
| **C1** | **B** — Analyst + Critic only | Researched TradingAgents (arXiv 2412.20138, TauricResearch repo) in depth before deciding. Its Trader and Portfolio-Manager roles are **LLMs that approve the trade directly** — the one thing `brain/models.py`'s `validate_human_identity` (and the fixed `_NON_HUMAN_IDENTITIES` set, which literally includes `"cursor"`/`"claude"`/`"fable"`) exists to forbid. Importing that topology hands promote/demote authority to a debate instead of the four gates + `anant`. Declined to reopen the session's own "no multi-agent debate as edge" rule. **Tutor** (decision-inert explanation pass over a finalized card) deferred to V1/V1.1, since it never touches confidence/gates. **Research-proposer swarm** (parallel agents drafting `Citation`s + `PROPOSED` `StrategySpec`s from external research) deferred as its own future block — feeds the existing human-gated loop, never confidence/gates/promote directly |
| **C2** | **E** — plain Python library runner (`agents/runner.py`, path locked) + thin Typer CLI wrappers | **No LangGraph.** The pipeline is a fixed two-LLM-call linear sequence with no model-decided branching — LangGraph solves dynamic/looping agent-flow problems this pipeline doesn't have, and would be the first dependency in a project whose entire stack today is `pydantic`/`duckdb`/`typer`/`hypothesis`/`pytest`/`exchange_calendars` (checked `pyproject.toml` directly). Implementation: **`instructor`** or **`pydantic-ai`** to bind LLM output directly to `EvidenceCard`/`CriticReview` schemas; **`litellm`** as the provider call interface; a fixture provider mirroring the existing `csv_fixture` pattern for offline CI |
| **C3** | **E** — `litellm` + fixture offline default | Confirmed `litellm`'s SDK is free/open-source (you only pay the underlying provider; the paid Proxy/Gateway/Enterprise tiers are a separate, unneeded product). Researched current free-tier terms directly: **live default = Gemini Flash** (`LLM_MODEL=gemini/<current-flash-alias>`, 1,500 req/day free, native JSON schema, no card). **Alternate = Groq** (`groq/llama-3.3-70b-versatile`, JSON mode + tool calling on all models, 1,000 req/day free). **GitHub Models excluded** — retires 2026-07-30. **Azure OpenAI ($100 credit) held in reserve**, not the V1 path — new subscriptions default to 0 TPM quota requiring an explicit increase-request with real turnaround (confirmed via Microsoft's own quota docs), not worth the ramp-up for this call volume. `.env.example` must disclose that Google's free tier may use prompts for training (low-stakes for public market data, stated explicitly rather than assumed) |
| **C4** | **E** — LLM stack importable only under `agents/`; sole `litellm` import site = `agents/llm_client.py` | Extend `test_security_scope.py` to fail on `litellm\|openai\|anthropic\|instructor\|pydantic_ai\|google.generativeai` anywhere else under `src/research_data/`. **Implementation, not new scope:** `agents/llm_client.py` uses `litellm.Router` (confirmed available in the open-source SDK, not gateway-only) with an ordered fallback chain — Gemini Flash → Groq → local Ollama — so one provider's rate limit never blocks the runner. Confirmed via clarifying question that "running almost all the time hunting for information" meant robustness for the already-scoped small call volume, **not** a continuously-running background research daemon — that idea stays scoped to the deferred research-proposer swarm (C1), not folded into C4 |
## Block D — Proposal / Citation Logistics
*Mechanism:* the compound loop (`citation → proposed spec → human approve → gates → promote/demote → journal lesson → next citation`) without an LLM proposer yet.
| ID | Decision | Key notes |
|---|---|---|
| **D1** | **E** (A+B+D; C — LLM claim extraction — deferred with the research-proposer swarm) | Deterministic CLI (`cite-add`, `cite-from-vault`, `cite-from-journal`), outside `agents/`. **Stable citation id = `hash(vault_relpath + content_hash(claims_section))`, not mtime.** Checked `brain/store.py`: `Citation.citation_id` defaults to a random UUID4 and the store has no `update_citation` — insert-only. So a note edit must produce a **new** citation row (old one stays untouched, so any past `PromotionDecision.evidence_citation_ids` keeps pointing at what was actually cited at decision time) — mtime-based hashing would either false-trigger on a no-op touch or, if implemented as an in-place update, silently mutate evidence behind a past decision. `cite-add` (manual) **warns**, does not block, on a normalized title/author match against `list_citations()` — nothing today prevents accidental duplicate literature entry. **Claims: empty allowed at ingest, non-empty required only at use** (when assembling `evidence_citation_ids` for a `PROPOSED` spec or `PromotionDecision`) — not a `Citation` model length validator |
| **D2** | **D, tightened** | Standing contract for any `PROPOSED` `StrategySpec` (human-authored in V1; an LLM proposer inherits the same contract in V1.1 — V1 AI still emits no specs, only `CriticReview`). **`n_trials` is already auto-counted today** via `BrainStore.count_tested_specs()` (`COUNT(DISTINCT spec_id) FROM brain_test_runs`) — global, not scoped to a hook family. Corrected Cursor's own draft, which proposed scoping the count to "specs sharing hook family": that would **under-count** trials and understate DSR's selection-bias deflation exactly as the strategy pack grows across families. **`declared_n_trials` rejected outright** — `Docs/PHASE2B_PROBLEM_STATEMENT.md`'s own risk register already names "DSR self-deception via trial accounting" and mitigates it by deriving the count from recorded runs, never a declared field; a manual override would be the first fabricated-adjacent number in this codebase's gate math. New fields `params_delta` + `parent_spec_id` (provenance only) added to `StrategySpec`; `params` itself stays the fully-merged, self-contained dict computed at propose-time, so `resolve_hook` and gate execution never walk a parent chain at runtime. `resolve_hook(hook_ref)` must succeed at **propose-time**, not just before approve (fail-closed early, matching every other check in this codebase) |
| **D3** | **D + structural tests, not prose-only** | Traced the actual call paths: `GateHarness()` is invoked with zero config args today, and strategy hooks take `universe` as a caller-supplied positional argument, never read from inside `params` — so the "backdoors" this question worried about don't exist *yet*, but only because nothing wires them, not because anything blocks them. Required, not optional: (1) `GateHarnessConfig`/`OOSParams`/`MonteCarloParams`/`WalkForwardParams`/`DeflatedSharpeParams` never constructed with non-default args outside `tests/`; (2) no strategy hook reads `universe`/`symbols`/cost-bps keys from `params`; (3) `kronos_reserved` never imported under `agents/`. Card/critic banned-token list = `BUY`/`SELL`/"guaranteed"/"risk-free" only — **do not** reuse `benchmark.py`'s `_EXECUTION_TOKENS` verbatim, since it also bans `HOLD`, correct only in that pure-data-reporter context |
| **D4** | **D** — Typer `brain propose/approve/reject/decide` + `analyze-symbol`/`critique-spec` on `cli.py`, plus a one-way vault mirror, **promoted into V1** (not deferred to F3 as Cursor first suggested) | Confirmed `cli.py` has zero brain commands today (only `init-db`/`ingest-prices`/`audit-prices`/`benchmark`), and `approve_spec`/`reject_spec`/`retire_spec` already call `validate_human_identity` at the store layer — a CLI wrapper adds no new place to bypass the gate. New commands go on `cli.py`'s Typer app, not the study script's `argparse` pattern (`scripts/run_quality_momentum_study.py` is explicitly a one-off study runner per this repo's own module map, not the general desk CLI). **Vault mirror pulled forward into V1** because it's one-directional (DB → vault markdown, read-only) and this entire questionnaire session's own pattern — reading Postmortem, Post Base, Kronos deep-dive, etc. to ground nearly every decision — demonstrates where this desk's actual working context lives. "DB wins on conflict" is literal: the vault file is regenerated from the DB row, never the reverse |
| **D5** | **D** — cite on lesson/exit `JournalEntry`; no auto critic/proposer | Checked `paper/engine.py`: every `JournalEntry` construction (five call sites across `execute_timed_entries` and `run_replay`) funnels through one private method, **`PaperEngine._journal()`** — that is the real single choke point, not "`PaperStore`'s write path" as first phrased. Wired as an **injected callback** (`on_lesson_journaled`), not a hard import — `paper/store.py` already imports `brain.models.validate_human_identity` (a stateless validator), but nothing in `paper/` imports `brain.store.BrainStore`, and a direct import there would be new, heavier coupling than anything else in this codebase. The orchestrating CLI (which already needs both stores) supplies the closure. `--cite-lesson` defaults **on** for real runs; opt-out is for synthetic/dev-fixture replays only, so debugging against fake data doesn't pollute the real citation graph |
## Block E — Eval, Safety, Cost
| ID | Decision | Key notes |
|---|---|---|
| **E1** | **D, tightened** | This repo already has a formal, numbered, hypothesis-fuzzed property-test convention (`test_property_no_fabrication.py` = Property 11, `test_property_quality_status.py` = Property 5). E1's new tests extend that series (own AI-hub namespace) rather than being a separately-invented "golden" style — fuzzing the B3 float-epsilon tolerance boundary with `hypothesis`, not just a couple of hand-picked planted-Sharpe fixtures. **Structural tightening on missing/contradictory data:** the runner must **never call the LLM at all** when `ScorePacket`/`DataEvidencePacket` quality is `MISSING`/`CONTRADICTORY` — Python builds the `INSUFFICIENT_DATA` card deterministically, mirroring `evidence.py`'s `EvidenceConstructionError` / the gates' fail-closed pattern. Tested by asserting **zero LLM-client invocations**, not just the output's action label. Citation-hallucination rejection follows `test_kronos_reserved.py`'s existing "construct a bad object, assert rejection" shape |
| **E2** | **C** — live smoke = real-packet allowlist check + planted false-Sharpe critic-reject | Documented in the Phase 3 SoT/runbook; `scripts/live_ai_card_smoke.py` and/or a `--live` env-gated CLI flag — **not** in default `pytest`. Nightly GitHub Action (option D) deferred until call volume justifies it. Live symbol still open, leans **NVDA** |
| **E3** | **C** | `.env.example` gains `LLM_MODEL`, `GEMINI_API_KEY=`, `GROQ_API_KEY=`, optional `OLLAMA_API_BASE`, `RESEARCH_DATA_LLM=fixture\|live`, and the training-disclaimer comment. The assembler sends `ScorePacket` + `evidence_refs` + the gate whitelist projection — **never raw `daily_ohlcv` bars** (cost, training exposure, and invention surface, all rejected). `max_tokens` + `litellm.Router` fail-fast pinned in `llm_client.py`. Live smoke prints pass/fail only at default verbosity, not full prompt bodies — mirrors the ingestion path's own `redact_secrets` spirit |
| **E4** | **C + one field, not full D** | No Brier math, no JSONL outcomes file, no new calibration table in V1. Checked `Thesis` (`paper/models.py`): it already has `spec_id: str \| None` linking to an originating `StrategySpec`, but nothing links a `Thesis` to the card that informed it. Added **`Thesis.source_card_id: str \| None = None`**, mirroring the exact existing `spec_id` pattern — free right now (no AI-hub `Thesis` rows exist yet, no migration) and irrecoverable if skipped, since there is no way to retroactively know which card a human was reading when a thesis opened. With that field, a future calibration job joins `JournalEntry.thesis_id → Thesis.source_card_id → EvidenceCard` entirely within existing stores — no new artifact needed, so Cursor's `data/cards/outcomes/` JSONL proposal was dropped as unnecessary mechanism. North-star doc must flag explicitly, not just as "no data yet": Brier scoring needs a **named binary predicted event** and a **calibrated probability** — action labels and `confidence` aren't that yet, and defining what's actually being predicted (outperform VOO over what horizon?) is an unresolved design question independent of data volume |
