# adx — Recommended Fixes
==Everything below is a recommendation, not a fact — the factual record lives in [[Source Claims]], [[Claims vs Implementation]], and the five [[Codebase Deep Read|Codebase\]] notes; this note exists solely to turn those findings into one prioritized, actionable list.==
## Goal
Turn every gap and discrepancy found across the static-reading pass ([[Source Claims]], [[Claims vs Implementation]], 2026-07-22) and the deeper, run-it-for-real pass ([[Codebase Deep Read]] and its five notes, 2026-08-07/08) into a single list — prioritized by what actually blocks the most, not by which pass found it. This is a real rewrite, not an appended patch: every item below was re-read against current evidence, and each one says whether it was hardened with new proof, stays as originally stated, or is new this pass.
## 0. Distribution — Fix Before Anything Else Matters
Nothing below is reachable if a new user can't install the tool. This tier didn't exist in the original list; it outranks every item that did.
- [ ] **Resolve the npm package-name collision.** `adx` on the real npm registry is a real, unrelated, essentially-empty package from 2019 (confirmed via `npm view adx` and an actual clean install — no working CLI results from it). Every one of the 8 packages uses the bare unscoped name, and `.changeset/config.json`'s release group is built around it — this was never a scoping mistake, and the package cannot currently be published to npm at all as configured. Real options: rename to a scoped package (`@ahnafyy/adx` or similar, immediate and free) or negotiate for the existing name (unpredictable, slow). Full detail: [[Distribution and Adoption Gaps]].
- [ ] **Add a LICENSE.** No `LICENSE` file exists at the repo root, and no `package.json` across all 8 packages declares a `license` field either — not even the file, not even the metadata. A real adoption blocker for any team doing dependency due diligence, independent of whether the code works.
## 1. Integrity Fixes — Highest Priority
These touch the product's actual accountability claim, not just its polish. Three of four items here are now backed by live reproduction, not a single reading of the source.
- [ ] **Capture a real signer identity.** `signedBy` is hardcoded to the literal string `'engineer'` in `packages/adx-gate/src/gate.ts` on every gate run, interactive or not. **Hardened:** reproduced live today against a fresh throwaway repo — the agency ledger entry read exactly `"signedBy": "engineer"`, matching the tool's own dogfooded history from July. Read `git config user.name` (or an equivalent identity source) instead.
- [ ] **Stop auto-approving Level 6 in CI with zero human input.** `packages/adx-gate/src/ui.ts` sets `agencyLevel: AgencyLevel.Resolve` on any non-blocked CI run. **Hardened, and stronger than originally stated:** tested three separate `adx.config.ts` variations (`minimumHumanAgencyRequired: AgencyLevel.Flag`, `enforceTasteCheck: false`, `minimumAdxScore: 99`) — every run produced an identical result. This isn't a config gap a team could close themselves; the CI path doesn't read `boundary` config at all. Either record CI-only approvals at a distinct, clearly-lower level, or require an explicit human step before Level 6 can ever be recorded.
- [ ] **`--exec` provisions a real isolated worktree and never uses it for the actual agent call.** `harness.ts` passes the worktree path to `assembleContext()` and `runVerificationHooks()` correctly — only `adapter.complete()`, the call that actually runs the agent, never receives it. **New this pass, proven live:** polled `git worktree list` mid-run and caught a real second worktree existing simultaneously with a file-write probe whose own reported `pwd` was the main repo root. This has been true since the very first commit that introduced `adx run` (`d1edd4e`) — not a regression. Full detail: [[Safety-Critical Gaps]].
- [ ] **`adx maintain override` — the fix the tool's own pre-commit hook tells a blocked user to run — doesn't exist.** Confirmed by running it (`ERROR Unknown command override`) and by searching full git history (never committed at any point). Docs present it as a real subcommand in the same style as the three that work; the hook prints the identical syntax when it fires. **New this pass.** Either implement it or stop telling users it exists.
- [ ] **Reconcile the gate's actual blocking logic with the documented "score below 60 blocks merge" threshold.** The code blocks on three unrelated booleans (`abstraction.flagged`, any tautological test, more than 3 drifted files), with no reference to the numeric score. **Not re-tested empirically this pass** — code hasn't changed since July, no reason to doubt the original finding, but this pass didn't specifically re-run it.
- [ ] **Fix or reword the "import cycles always score 0" claim.** The code gives cyclic files a flat +0.5 risk bonus, not a forced floor. **Not re-tested empirically this pass** — same status as above, still live and unchanged in the docs as of this session's live-docs recheck.
## 2. Safety — Things That Can Corrupt or Destroy Real Work
- [ ] **Mutation testing can permanently corrupt a real source file if interrupted mid-run.** `runMutationTest()` writes a mutated file to disk, runs the test command, then restores the original in a `finally` block — which never runs if the process is killed. **New this pass, proven, not inferred:** `SIGKILL`'d a real run ~200ms into a 10-second test window; the file was left permanently mutated (`true` → `false`), with zero warning. Full detail: [[Safety-Critical Gaps]].
- [ ] **`provisionWorktree`/`teardownWorktree` swallow every failure silently.** Both catch blocks are comment-only, no logging — a user cannot tell "isolation wasn't requested" from "isolation failed unexpectedly." **New this pass.**
- [ ] **Document `adx sweep --fix` / `--auto` / `--dry-run` / `--comments`.** All four exist and work; the CLI's own `--help` text now describes them, but the public docs site still doesn't (re-checked live this session). **Unchanged** from the original finding.
- [ ] **Decide `adx sweep --auto`'s CI posture explicitly.** **Unchanged.**
## 3. Process and CI — Why Bugs Ship and Survive
New tier this pass — the original review didn't look at the project's own build/typecheck/CI tooling at all.
- [ ] **Wire `pnpm typecheck` into CI, and fix `pnpm -r`'s bail-on-first-failure so it can't hide a whole package's errors.** `.github/workflows/adx.yml` runs only `pnpm build` and `pnpm test` — no typecheck step exists anywhere in it. The root `pnpm typecheck` script does exist, but `pnpm -r run typecheck`'s default behavior aborts at the first package failure (`adx-gate`'s own separate, day-one `exactOptionalPropertyTypes` errors), so `adx-cli` — where the crash below lives — never gets checked in the intended workflow. **New this pass, and the single highest-leverage fix found this session:** TypeScript itself catches the crash bug instantly when run in isolation; this is the only reason it shipped and survived a month. Full trace: [[Process and CI Gaps]].
- [ ] **Fix the 8 real, currently-uncaught TypeScript errors.** 2 in `adx-gate/src/ui.ts` (present since the first commit), 6 in `adx-cli` (`init-mcp.ts`'s `generateCopilotInstructions is not defined`, 4 in `maintain.ts`, 1 in `run.ts`). **New this pass** — confirmed via `pnpm --filter adx run typecheck` (the package's real name is `adx`, not `adx-cli`).
- [ ] **Fix `adx init`'s unconditional crash.** `generateCopilotInstructions()` was correctly defined in `init.ts` at commit `7bda28e`, then dropped when that file was split into `init-agents.ts`/`init-generators.ts`/`init-mcp.ts` at `d5d2610` — a refactor meant to fix a file adx's own tooling would flag as bloated. Reproduced across every flag combination (`--force`, `--worktree`, bare). **New this pass, and arguably the most severe single bug found** — the tool's own onboarding command has never worked since that split, and nothing catches it (see above). Full detail: [[Dead-on-Arrival Code]].
- [ ] **Unify the two BER implementations.** The CLI's `computeBER` and the MCP tool's inline calculation diverge. **Hardened with live numbers:** on the identical throwaway-repo state, the CLI reported `ber.score: 100` and the MCP tool reported `ber: 50` — a 15-point swing in the composite ADX score (97 vs. 82) from the same code. The MCP version carries its own `// Minimal BER` comment — it was written as a deliberately simplified stand-in, not accidental drift, and never reconciled with the real `computeBER`.
- [ ] **Regenerate the stale README badge.** `.adx/badge.json` reads 79/100; the repo's own `d5d2610` commit message says "ADX score: 79→85/100" and the badge file was never updated to match. A fresh run today confirms 85/100 is current. **New this pass.**
- [ ] **Populate `test-log.txt` for real.** `packages/adx-gate/src/gate.ts` hardcodes `testLog: ''` on every run. **Not re-tested empirically this pass** — code unchanged, original finding stands.
- [ ] **Fix the `harness.context.memory` type mismatch.** Docs say `'disk' | 'none'`; code type is `'disk' | 'memory'`. **Unchanged.**
## 4. Dead Code / Config Cleanup
- [ ] **Either implement `router` or remove it from the type.** `harness.control.router` accepts three values; nothing in `harness.ts` ever reads it. **Hardened:** reconfirmed via direct grep this pass — zero references anywhere.
- [ ] **Wire `enforceTasteCheck` into the gate, or delete the flag.** Taste analysis runs unconditionally regardless of its value. **Hardened, and the docs got worse, not better:** the live docs site now explicitly states this flag controls "whether to run the taste deficit analysis... as part of `adx gate`" — a more specific, more confidently false claim than what the July review found.
- [ ] **Make `requireExplanationInvariants` actually contextual, or redocument it honestly.** Any non-empty list triggers one blanket prompt regardless of category. **Hardened, same pattern:** the live docs now explicitly assert "the gate checks diff content to detect these" — directly contradicted by `ui.ts`'s actual `.length > 0` check.
- [ ] **Remove `harness.hooks.maxRetries`, or implement it.** Typed, defaulted to 3, written into every generated config — never read by the actual retry loop, which just continues unconditionally up to `maxIterations`. **New this pass**, same shape as `router`.
- [ ] **Include the taste-deficit score in the gate score, or explicitly label it advisory-only.** **Unchanged.**
- [ ] **Publish a reference page for `adx ratchet`, or stop listing it as a peer command to `adx gate`.** No CLI subcommand exists. **Hardened with a new nuance:** confirmed live that the MCP tool `adx_ratchet` genuinely works (called it directly, got a real response) — it's specifically the CLI surface that's missing, not the whole feature.
- [ ] **Fix or remove `adx-intellij`'s dead Tools-menu actions and broken `getFileTds`.** `plugin.xml` registers two actions whose classes were never committed in any commit, ever. `AdxService.getFileTds()`'s regex expects a JSON shape (`tdsScore`) that matches the MCP server's output, not the CLI's real nested `tds.score` shape — but the Kotlin code calls the CLI. **New this pass** — this whole package wasn't reviewed in the original pass at all. Full detail: [[Dead-on-Arrival Code]].
- [ ] **Extract `fileExists()` and `bar()` into shared utilities.** `fileExists()` is copy-pasted verbatim across 5 files in `adx-cli`; `bar()` (progress-bar rendering) is reimplemented with diverging parameters across 4 files. **New this pass** — real, if minor, code-quality debt in the exact shape adx's own tooling exists to catch.
- [ ] **Fix `.tsx` import resolution in `adx-shape`.** `resolveImport()` always appends a literal `.ts`, so any `.tsx`-to-`.tsx` import silently fails to resolve — undercounts FRR and misses cycles on any React/JSX codebase. **New this pass**, untested by the package's own test suite.
- [ ] **Fix the broken logic/type split in `adx sweep`'s orphan scoring.** `sweep.ts`'s `logicOrphans` filter has an unused loop variable that degenerates to a pure capitalization check; the real fix requires `extractExports` to actually carry the AST declaration kind through, which it currently discards. **New this pass.**

- [ ] **Disclose the undocumented internal formulas** (TDS 0.6/0.4, FRR 0.15/0.25/0.5, gate score 0.4/0.4/0.2). **Unchanged.**
- [ ] **Caveat `estimatedTokens` as an approximation.** **Unchanged.**
- [ ] **Cite a real source for the "7–8% fewer tokens, 34% fewer file revisits" claim, or stop stating it as fact.** No benchmark file, dataset, or citation exists anywhere in the repo or docs for these specific numbers — they appear in `abstraction.ts`'s comment and two READMEs, with "34%" reused for a different, unrelated claim in the second one. **New this pass.** Full detail: [[Distribution and Adoption Gaps]].
- [ ] **Document the `adx-vscode` extension** — install path, marketplace link, what its "run gate" command actually does. **Unchanged.**
- [ ] **Document `adx-intellij` at all** — it currently has zero mentions anywhere: not the README's package table, not the docs site, not `pnpm-workspace.yaml` (correctly, since it's Gradle/Kotlin). **New this pass.**
- [ ] **Document that MCP's `adx_gate_check` only runs Layer 1.** **Hardened:** called it live this pass and confirmed the response shape genuinely contains only abstraction-analysis fields — no mutation or intent-cross-reference data at all.
